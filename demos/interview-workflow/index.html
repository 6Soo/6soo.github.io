업무 자동화 · 문서 파이프라인

면접 녹취 자동 기록 파이프라인

화상 면접이 끝나면 녹취 문서가 자동으로 감지되어 마크다운 기록으로 쌓이고, 비어 있는 평가 칸은 초안으로 채워진 뒤 사람이 원문과 대조해 확정합니다. 이 화면은 그 흐름을 그대로 체험할 수 있는 합성 데이터 데모입니다.

  • 5단계 자동 파이프라인
  • 파일 ID 기반 중복 방지
  • 사람 확정 전제 설계

이 데모는 브라우저 안의 정적 HTML/CSS/JS만으로 동작합니다. Google Apps Script, Drive, Gmail, GitHub API, AI 모델을 실제로 호출하지 않으며 입력된 내용은 어디에도 전송되지 않습니다.

어떤 문제를 해결했나

수작업 복붙의 누락

면접이 끝날 때마다 사람이 녹취 문서를 찾아 복사하고 파일명을 맞췄습니다. 면접 횟수가 늘면 기록 누락과 파일명 오타가 함께 늘었습니다.

덮어쓰기와 평가 손실

자동화로 바꾸는 과정에서, 이미 만든 평가가 다음 동기화에 밀려 지워질 위험이 생깁니다. 파일 단위 식별로 재동기화 대상을 분리해야 했습니다.

초안과 확정 사이 간극

요약 문장을 자동 생성해도 그대로 믿으면 원문과 어긋납니다. 초안은 반드시 사람 대조 전제로 두고, 확인 전에는 확정 상태로 보지 않게 했습니다.

핵심 흐름 데모

1. 파이프라인 단계 실행

단계를 순서대로 실행하면 상태 표시가 오른쪽으로 전이되고 로그가 쌓입니다. 각 단계 카드를 눌러하면 그 단계가 원본에서 어떤 역할을 하는지 볼 수 있습니다.

    실행 로그

    2. 새 트랜스크립트 등록

    등록한 파일 ID가 이미 동기화된 목록에 있으면 덮어쓰지 않고 건너뜁니다. 원본 규칙인 파일 ID로 추적해 재동기화 시 덮어쓰지 않음을 그대로 재현했습니다.

    3. 기록 카드와 사람 확정

    기록 목록

    카드의 평가 초안 작성 폼에 요약·강점·우려·추천을 넣고 저장하면 초안이 생깁니다. 원문 대조 확인을 체크하고 확정을 눌러야 상태가 확정으로 바뀝니다.

    이 조건에 맞는 기록이 없습니다. 필터를 '전체'로 바꿔 보세요.

    원본에서 확인한 구조

    흐름

    면접 녹취 문서 생성
  └─ 시간 트리거가 새 문서 감지
       └─ 본문 추출 → 마크다운 변환 (평가 템플릿 삽입)
            └─ 저장소 records/ 폴더로 자동 커밋
                 └─ 후속 자동화 워크가 평가 초안을 채움
                      └─ 사람이 원문 대조 후 확정

    확인한 설계 포인트

    • 파일 단위 식별자로 재동기화 시 기존 평가를 보존
    • 평가 초안은 빈칸인 기록에만 채우고, 사람이 확정
    • 원문에 없는 내용은 만들지 않는 원칙을 문서화
    • 영상은 저장하지 않고 텍스트와 링크만 보관
    • 수동 기록용 마크다운 템플릿을 함께 제공
    • 메일 라벨 기반 과제 제출 아카이브를 같은 자동화에 결합

    기술 스택

    • Google Apps Script (.gs)
    • Google Docs / Drive
    • Gmail 라벨 필터
    • GitHub REST API
    • GitHub Actions
    • clasp
    • Node.js (.mjs)
    • HTML / CSS / JavaScript

    데모와 실제 구현의 차이

    • 실제 호출 없음. Drive 감지, GitHub 커밋, GitHub Actions 실행, AI 모델 호출을 모두 모사했습니다. 데모 동작은 브라우저 메모리 상태에서만 일어납니다.
    • 합성 데이터. 트랜스크립트 본문, 지원자 코드, 평가 문구는 모두 지어낸 예시입니다. 실제 서비스의 기록, 메일, 지원자 자료는 사용하지 않았습니다.
    • 단순화한 AI 평가. 데모는 사람이 입력한 값을 초안으로 저장·표시합니다. 원본의 모델 프롬프트와 출력 형식은 공개하지 않았습니다.
    • 확인 범위 밖. 서버 인증 설정, API 할당량, 실패 재시도, 대용량 문서 처리, 권한 설정은 검증하지 않았습니다.
    • 운영 규칙 비공개. 개인정보 보관 기간 등 사내 운영 결정 사항은 데모에 반영하지 않았습니다.
    • 접근성 참고. 이 데모 화면은 키보드 조작과 반응형 레이아웃을 고려했고, 데모 내부 로직은 외부 시스템 연동 검증이 불가능해 수동 확인 범위입니다.
