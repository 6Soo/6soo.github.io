카드뉴스 1편을 데이터로 다루고, 규칙으로 걸러내고, 일괄로 뽑는 파이프라인

인스타그램 카드뉴스 시리즈는 카드 내용을 코드로 관리한다. 한 시리즈가 카드 데이터 한 묶음이고, 데이터에서 게시용 세로 이미지 전체를 일괄 생성한다. 이 데모는 그 흐름에서 실제로 손으로 확인하는 단계만 재현한다. 텍스트·사진·지표는 모두 합성 예시이며 외부 호출은 없다.

  1. 1카드 데이터 작성
  2. 2규칙 검수(게이트)
  3. 3일괄 렌더
  4. 4기록 페이지

1. 카드 데이터

한 장의 카드 내용만 바꿔 보면 오른쪽 미리보기가 즉시 갱신된다. 한 폴더 = 한 게시물.

2. 미리보기 게시 규격 4:5 (1080×1350 축척 재현)

원본 구현은 300×375 원판을 3.6배 확대해 1080×1350로 캡처한다. 글리프는 벡터라 확대 후에도 선명하고 크기 비율이 원판과 그대로 유지된다.

    3. 일괄 렌더 시뮬레이션

    검수 결과가 통과면 렌더만 돌릴 수 있다. 여기선 서버 작업 없이 카드별 완료 상태와 라벨만 재현한다. 실제 파일·업로드는 만들어지지 않는다.

    4. 기록 페이지

    렌더 뒤 카드별로 한 장씩 놓이는 검토용 페이지 묶음. 여기서는 카드 목록만 표시한다.

    원본에서 확인한 사실

    • 카드뉴스 렌더 스크립트가 시리즈 폴더의 cards.mjs를 읽어 카드마다 1080×1350 PNG를 생성한다.
    • 비주얼은 기준본 카드 CSS를 그대로 쓰고 내용 슬롯만 데이터로 채운다(단일 원천 원칙).
    • 쪽번호 규칙이 코드에 박혀 있다. 표지는 몇 장이든 게시할 때 1쪽, 내지는 2쪽부터 센다.
    • 사진 없는 단색 카드는 기본 금지이고, 종이 카드는 8·9장에만 쓰는 것이 문서화된 규칙이다.
    • 이미지형 산출물은 PDF로 묶지 않고 PNG 원본을 그대로 전달한다는 전달 규칙이 있다.

    데모와 실제 구현의 차이

    • 이 데모는 순수 정적 HTML/CSS/JS다. 원본은 Node 스크립트와 로컬 헤드리스 브라우저로 PNG를 실제로 만든다.
    • 사진은 합성 색면으로 그린다. 원본은 실사진 파일 경로를 배경으로 넣는다.
    • 규칙 검수는 문서화된 규칙을 시각화한 것이며, 원본의 검사 스크립트 실행 결과와 동일한 판정은 아니다.
    • 외부 API 호출, 인증, 실제 저장은 하지 않는다. 입력 내용은 화면 안에서만 바뀐다.
    • 회사와 사람 이름, 실제 서비스 주소는 공개하지 않는다.
