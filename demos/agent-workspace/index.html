에이전트 작업 세션 콘솔

여러 코딩 에이전트를 동시에 돌리면 어떤 에이전트가 무엇을 하고 있는지, 지금 무엇을 허가해야 하는지, 어디까지 끝났는지를 한 화면에서 놓치기 쉽습니다. 이 데모는 지시 → 실행 → 권한 확인 → 후속 지시 → 다른 에이전트로 위임 흐름을 그대로 눌러 보게 합니다.

화면의 모든 에이전트 이름, 모델명, 로그, 지시는 실제 기록이 아니라 데모용으로 미리 만들어 둔 합성 데이터입니다. 외부 API 호출, 실제 코드 실행, 파일 저장, 전송은 하지 않습니다.

조작해 보는 데모

1 새 작업 실행

원본에서 제공자를 고르는 방식과 동일한 목록을 예시로만 옮겼습니다.

워크트리를 고르면 별도 브랜치 이름이 합성으로 생성됩니다.

입력한 문장의 키워드에 따라 실행 단계가 달라집니다. 어떤 문장이든 동작합니다.

작업 지시를 1자 이상 입력해 주세요.

2 실행 중인 세션

아직 실행 중인 작업이 없습니다. 왼쪽에서 지시를 입력하고 ‘에이전트 실행’을 눌러 주세요.

    전송하면 같은 세션 뒤에 단계가 덧붙습니다. 실제 전송은 하지 않습니다.

    3 에이전트 트랙

    실행된 에이전트가 여기에 쌓입니다.

      협업 스킬로 위임하기

      원본 저장소에 함께 들어 있는 스킬 중 세 가지를 시뮬레이션합니다. 선택하면 새 에이전트와 함께 ‘인수인계 브리핑’이 만들어집니다.

      인수인계 브리핑

      권한 확인이 왜 필요한가

      실행 도중 에이전트가 파일 수정이나 명령 실행을 요구할 때, 사용자가 ‘허용 / 거절’을 고르는 지점이 이 데모의 핵심입니다. 아래 권한 이름과 구분은 원본 문서에서 확인한 구조를 그대로 옮긴 것입니다.

      데몬 권한과 그 범위
      권한허용 범위

      원본에서 확인한 내용

      확인한 기능

      • 에이전트를 관리하는 로컬 서버 데몬이 있고, 데스크톱 앱과 모바일 앱, 웹, CLI가 그 데몬에 붙는 구조입니다.
      • 제공자는 Claude Code, Codex, GitHub Copilot, OpenCode, Pi 다섯 가지를 인터페이스에서 선택할 수 있습니다.
      • CLI에는 실행(run), 목록(ls), 출력 첨부(attach), 후속 지시(send) 같은 명령이 있습니다.
      • 워크스페이스를 로컬 또는 워크트리로 격리해 만들고, 프로젝트와 워크스페이스를 관리·이름변경·보관할 수 있습니다.
      • 권한은 역할 이름이 아니라 daemon.read, workspace.write 같은 의미 단위 권한으로 나뉘며, 없는 권한은 거절로 처리됩니다.
      • 일정과 하트비트 같은 반복 실행 수단, 여러 에이전트를 다루는 스킬(handoff, advisor, committee)이 함께 제공됩니다.

      기술 스택

      • TypeScript 모노레포(npm workspaces)
      • Electron 데스크톱 앱 / Expo 기반 모바일 앱(웹 포함)
      • WebSocket 기반 데몬 API와 MCP 서버 제공
      • 종단 간 암호화 릴레이 패키지, 플러그인 패키지
      • Vitest, Playwright, oxlint, oxfmt 검증 도구

      이 데모의 한계

      • 데몬, 실제 에이전트 프로세스, 에이전트 CLI 인증은 실행하지 않습니다. 로그와 단계는 미리 정해 둔 대본입니다.
      • 모델 목록과 단계 흐름은 실제 응답이 아니라 데모용 예시입니다.
      • 음성 제어, 릴레이 터널, 일정/하트비트 실행, 플러그인 설치는 이 데모 범위 밖입니다.
      • 권한 표는 설명용으로, 실제 권한 부여나 차단 로직은 구현하지 않았습니다.
