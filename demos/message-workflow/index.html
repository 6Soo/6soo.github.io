업무 자동화 · 수신 파이프라인

메신저로 들어온 업무 지시를
도메인 작업으로 배분하는 파이프라인

개인 메신저에는 공식 수신 API가 없어 창 열거, 알림 수신, 클립보드 복사 같은 아웃오브프로세스 관측만 쓸 수 있습니다. 그래서 이 프로젝트의 난이도는 전부 “수신”에 몰려 있고, 그 다음 단계는 규칙과 승인 게이트로 이어집니다. 이 화면은 그 흐름을 원문 복사 한 번부터 도메인 배분까지 그대로 흉내 낸 합성 데모입니다.

  • 수신 알림 주 수신기 + PC 클립보드 보정
  • 적재 안정 ID 기반 JSONL, 중복 제거
  • 승인 자동 발송 전 사람 확인 게이트

파이프라인 5단계

  1. 1수신앱 패키지 필터 + 채팅 제목 정확 일치
  2. 2파싱날짜, 발신자, 시각, 여러 줄 본문
  3. 3분석업무 유형 감지 후 도메인 라우팅
  4. 4승인실행 전 사용자 확인, 반려 가능
  5. 5디스패치대상 저장소 작업 골격 생성

        원본에서 확인한 구현

        수신 경로

        Android 알림 주 수신으로 전환하고, PC 쪽은 창 구조를 직접 만지는 대신 클립보드 복사로 본문을 보정합니다. 창 구조 실측에서 UI 자동화 경로는 실패하고 클립보드 경로가 동작한 것이 전환 근거입니다.

        적재 규칙

        복사 본문을 파싱해 날짜, 발신자, 시각, 여러 줄 본문을 분리하고, 안정 ID로 중복을 제거한 뒤 JSONL에 이어 붙입니다. 반복 실행해도 같은 항목이 쌓이지 않습니다.

        승인과 이관

        실행 전 승인은 Telegram 인라인 액션으로 받고, 모든 답변 원문을 보존한 뒤 업무 한정 규칙과 전역 규칙을 나눠 저장합니다. 디스패치는 골격까지만 만들고 외부 효과는 다음 승인을 기다립니다.

        이 프로젝트는 카카오톡에 개인 대화 수신 API가 없다는 전제를 전제로, 아웃오브프로세스 관측만 쓰는 형태로 로컬 자동화 도구를 조합해 구축한 개인 운영 자동화 사례입니다. 도구 원본 코드를 복사해 둔 것이 아니며, 연동한 각 오픈소스 도구의 저작권은 원작자에게 있습니다.

        데모와 실제 구현의 차이

        • 수신 실제 구현은 안드로이드 알림 수신기와 Windows 창 제어를 사용합니다. 이 데모는 텍스트를 직접 붙여 넣습니다.
        • 분석 실제 구현은 로컬 AI CLI를 호출하고 실패 시 다른 CLI로 폴백합니다. 이 데모는 화면에 있는 키워드 규칙표만 씁니다.
        • 승인 실제 구현은 다른 메신저의 일회용 인라인 액션으로 승인을 받습니다. 이 데모는 버튼 두 개로 대체했습니다.
        • 저장 실제 구현은 로컬 JSONL과 데이터베이스 계약으로 이어 붙입니다. 이 데모는 브라우저 메모리만 쓰고 새로고침하면 사라집니다.
        • 외부 효과 이 데모는 외부 API 호출, 발송, 결제, 실제 저장을 하지 않습니다. 모든 이름과 수치는 합성입니다.
