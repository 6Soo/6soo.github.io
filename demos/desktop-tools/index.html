업무 자동화 · Windows 데스크톱 유틸리티

다중 모니터에서 관리 창을 한 번에 배치하는 흐름

실제 서비스 대신 브라우저를 띄우는 로컬 도구를 다뤄 본 experience입니다. 이 페이지는 그 도구의 조작 흐름만 골라 순수 HTML로 재현했습니다. 화면의 모니터, 프로세스, 창 좌표는 전부 예시 값이며 외부로 전송되거나 저장되지 않습니다.

  • 외부 API 호출 없음
  • 폼 전송 없음
  • 순수 정적 파일

원본에서 확인한 구현

아래 항목은 저장소 코드에서 함수와 클래스의 이름과 구조로 확인한 내용입니다. 화면에 표시되는 수치나 효과는 측정값이 아니라 예시입니다.

  • 모니터 열거 디스플레이 목록을 모아 위치를 비교하고, 가장 왼쪽에 있는 모니터를 고르는 함수가 분리되어 있습니다.
  • 실행 파일 탐색 설치된 브라우저 실행 파일 후보 목록을 만든 뒤, 선택한 대상을 자식 프로세스로 실행합니다.
  • 프로세스 정리 실행한 프로세스의 트리를 집어 Job Object로 묶어, 종료 시 자식까지 함께 회수합니다.
  • 창 탐색 · 핫키 대상 프로세스에 속한 창을 찾는 단계와, 키보드 후크를 다루는 클래스가 존재합니다.

조작 데모

1) 대상 모니터 선택 → 2) 실행 옵션 지정 → 3) 실행 → 4) 핫키 등록 → 5) 정리

1

대상 모니터 선택

모니터 카드를 클릭하면 창을 놓을 좌표와 DPI 배율이 계산됩니다.

선택된 모니터가 없습니다.

2

실행 옵션

실행 시 프로세스 트리 구성에 반영됩니다.

먼저 대상 모니터를 선택하세요.

3

실행 결과

창 배치 결과와 묶인 프로세스 트리입니다.

아직 실행 전입니다.

4

핫키 등록

입력 칸을 클릭한 뒤 실제로 키를 눌러 조합을 등록합니다. 브라우저가 실행 중이어야 등록됩니다.

등록된 핫키가 없습니다.

조합은 Ctrl 또는 Alt 중 하나와 다른 키 한 개로만 등록됩니다.

5

작업 로그

이 데모 안에서만 쌓이는 기록입니다. 새로고침하면 지워집니다.

    실제 구현과 데모의 차이

    원본 도구

    • Windows API를 직접 호출해 창과 프로세스를 만듭니다.
    • 실제 디스플레이 배치를 읽고 실제 창을 움직입니다.
    • Job Object로 자식 프로세스까지 함께 종료합니다.
    • 임시 프로필 폴더를 만들어 쓰고 나면 지웁니다.

    이 데모

    • 화면에 있는 값은 모두 예시이며 실제 창을 만들지 않습니다.
    • 브라우저 실행은 목록을 그리는 동작으로 대체했습니다.
    • 정리는 메모리 상태만 되돌립니다.
    • 파일 저장, 네트워크 전송, 실행은 전혀 하지 않습니다.

    이 데모는 원본 도구의 소스를 복사하지 않고, 확인된 동작 구조를 바탕으로 새로 만든 예제입니다. 회사명과 운영 서비스명은 공개하지 않으며, 성과 수치를 제시하지 않습니다.
