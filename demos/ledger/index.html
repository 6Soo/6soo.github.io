법인카드 비용 분류 자동화
규칙 대화형 장부 데모

여행사 법인카드 비용처리는 사람이 매번 같은 판단을 반복하는 업무입니다. 원본 프로젝트는 카드사 사용내역 수집 → 비용 분류 판단 → 장부 기록 → 상태 표시를 한 흐름으로 묶고, 반복되는 판단은 규칙 대화로 규칙으로 남기는 구조입니다. 이 페이지는 그 실제 사용자 흐름만 정적 HTML로 재현한 체험용 데모입니다.

  • 1사용내역
    가져오기
  • 2행별 검증
    중복 판정
  • 3미분류 건
    규칙 대화
  • 4규칙 적용
    장부 합계

이 데모의 회사명·가맹점명·금액·승인번호는 전부 가상의 합성 값입니다. 실제 카드 내역, 실제 장부, 실제 AI 모델, 실제 외부 API는 연결되어 있지 않습니다.

4규칙 대화

원본의 규칙 대화는 최대 5개 질문만 묻고, 이미 답한 질문은 다시 묻지 않습니다. 이 데모도 같은 순서로 질문하고, 답을 마치면 규칙이 어떤 행에 무엇을 쓸지 미리 보여준 뒤 적용합니다.

적용된 규칙

원본에서 확인한 구현

확인된 사실

  • 가져오기 계약의 필수 열은 occurred_on, merchant, amount_krw이며, 필수 열이 없으면 파일 자체를 거부하고 행 단위로 날짜 형식·숫자 금액·0원 제외를 검사합니다.
  • 행 식별은 안정 키와 내용 다이제스트를 분리합니다. 승인번호가 있으면 카드뒷자리와 승인번호로 키를 만들고, 같은 키에 다른 내용이 들어오면 충돌로 표시합니다.
  • 파일 단위는 내용 해시로 배치 식별자를 만들어, 같은 파일을 다시 올리면 새 행을 쌓지 않고 기존 결과를 재사용합니다(멱등).
  • 분류 상태는 자동 분류(여행 지정 열이 허용 목록에 있을 때)와 미분류로 갈립니다. 취소 플래그가 있으면 취소, 금액이 음수면 환불로 구분합니다.
  • 규칙은 조건 필드(가맹점 정규화값·카드 종류·거래 방향)에 eq/in/neq 연산자로 매칭하고, 효과 필드(여행 지정·비용 항목·비고 서식)만 씁니다.
  • 규칙 대화는 최대 5개 질문을 고정 순서로 묻고, 답변을 저장한 뒤 규칙을 만들도록 되어 있습니다.
  • 서로 다른 값을 쓰는 활성 규칙이 겹치면 충돌을 보고만 하고 자동 해소하지 않으며, 해결 방법은 기존 규칙 대체 또는 조건 좁히기로 선택하도록 되어 있습니다.
  • 같은 값을 쓰는 규칙이 이미 있으면 중복 효과로 보고해 같은 값을 다시 쓰지 않습니다.

구현 범위와 제한

  • 이 데모는 순수 정적 HTML/CSS/JavaScript입니다. 서버, DB, 원본 파일, 원본 소스 코드와 무관합니다.
  • 식별자 해시는 원본의 SHA-256 대신 데모용 축약 해시를 씁니다. 안정 키와 내용 다이제스트를 분리한다는 설계는 동일합니다.
  • 실제 AI 모델 호출, 카드사·은행 API, Google Sheets 업로드, 메일 수집, 로그인·인증은 원본에서도 이 데모 범위 밖이며 여기서도 동작하지 않습니다.
  • 비용 항목·여행 목록은 가상의 합성 목록이며 실제 회사 기준의 계정과목 체계가 아닙니다.
  • 브라우저를 닫으면 상태는 사라집니다. 서버 저장·파일 저장·외부 전송은 하지 않습니다.
