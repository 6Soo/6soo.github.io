약속 감시 브리핑과 산출물 렌더 파이프라인

여러 운영 도구를 한 저장소에서 관리하는 구조를 실제로 쓰는 중에 정리한 사례입니다. 에이전트 세션 기록에서 아직 끝나지 않은 약속을 자동으로 뽑아 재확인 기한과 함께 브리핑하고, 완성된 HTML 문서를 브라우저 엔진으로 벡터 PDF와 고해상도 이미지로 굽습니다.

  • 문서 저장소운영 도구 + 산출물 + 검증 문서를 한곳에
  • 핵심 문제보낸 뒤 확인할 날이 기록되지 않음
  • 해결대기 상태와 재확인 기한을 강제

어떤 문제를 풀었나

문제

여러 저장소와 도구를 쓰다 보면 시스템 사이의 데이터가 사람 손을 거칩니다. 예약 정보가 예약 쪽에 있는데, 다음 절차에 필요한 명단을 다시 옮겨 적어야 합니다. 특히 외부 업체에 보낸 요청의 답이 왔는지 확인하는 날짜가 어디에도 남지 않아 회신 누락이 그대로 사고가 됩니다.

설계 방향

대규모 재작성 대신 기존 도구를 그대로 두고 가장 많이 쓰는 곳을 데이터 축으로 삼고, 나머지는 그 축을 참조하는 도구로 정리했습니다. 그리고 기록을 남기는 문서 저장소를 만들어 의사결정과 우선순위가 한곳에 쌓이게 했습니다.

원본에서 확인한 구현

아래 내용은 저장소의 README와 도구 소스에서 직접 확인한 사실입니다. 성과 수치는 포함하지 않습니다.

  • 추출 파이프라인

    세션 기록을 주기적으로 증분 스캔해 규칙으로 후보를 선별하고, 구조화한 뒤 대기 목록에 넣고, 세션 시작 시 브리핑으로 되돌려주는 흐름이 문서에 명시되어 있습니다.

  • 대기를 1급 상태로 두는 규칙

    “상대 회신 대기”를 독립 상태로 두고 재확인 기한을 반드시 정하게 합니다. 기한이 지나면 브리핑 맨 위에 경고로 올라온다는 설계가 원본 문서에 기록되어 있습니다.

  • 되먹임 고리 차단

    스크립트가 스스로 만든 브리핑 문장을 다시 후보로 뽑는 고리를 막기 위해 표식을 남기고 스캔에서 제외합니다. 구조화 호출이 실패한 후보는 다음 회차에 재시도하도록 보존합니다.

  • 문서 렌더 도구

    HTML 원고를 브라우저 엔진으로 PDF(배경색 인쇄, HTML의 페이지 여백 우선 적용)와 2배 해상도 PNG(라이트·다크 강제, 전체 세로 길이 캡처)로 변환하는 스크립트 두 개가 저장소에 있습니다.

조작 가능한 데모

아래 모든 기록과 날짜는 화면 안에서 만든 합성 데이터입니다. 서버로 전송하거나 파일로 저장하지 않습니다.

  1. 합성 세션 기록을 스캔해 약속 후보를 찾습니다.
  2. 찾은 후보를 골라 재확인 기한이 있는 대기 항목으로 등록합니다.
  3. 브리핑에서 기한 상태를 보고 처리합니다.
