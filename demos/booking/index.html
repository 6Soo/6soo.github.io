여행 예약의 입금 정산과 대장 명단 자동화

여행사에서 예약이 접수된 뒤 실제로 벌어지는 일을 그대로 재현한 흐름 데모입니다. 예약 건에 입금을 기록하면 미수 잔액과 그룹별 정산 진행률이 바로 계산되고, 대장(인수인계 담당자)에게 넘길 명단을 개인정보 표시 규칙까지 포함해 출력할 수 있습니다.

이 화면이 재현하는 업무 흐름

  1. 1
    예약 접수

    같은 카페 회원이 여러 명을 한 번에 묶어 예약하면 그룹 번호로 묶여 들어옵니다.

  2. 2
    입금 대조

    입금일과 금액을 기록하면 미수·부분 입금·납부가 자동 구분됩니다.

  3. 3
    대장 명단

    투어별 대장이 확인할 명단을 만들고, 고유식별정보는 항상 가리고 내보냅니다.

  4. 4
    일정·명단 내보내기

    항공·숙소·보험 자료를 형식별로 나눠 받는 구조를 이 데모에서는 목록으로 축약해 보여줍니다.

정산 요약

아래 값은 현재 화면에서 입력한 입금 기록으로만 계산됩니다.

행의 상태 변경 버튼을 누르면 미수 → 부분 입금 → 납부가 순환하고, 바로 위 요약 수치가 다시 계산됩니다.

대장용 명단 미리보기

실제 서비스는 대장 화면 응답에 주민번호·여권 원문을 넣지 않습니다. 이 데모에서 가리기를 끄면 합성 원문이 보이므로, 실제 운영에서는 불가능한 동작입니다.

내보내기 미리보기

원본은 항공·숙소·보험을 각각 형식이 다른 파일로 내보내는 API를 둡니다. 이 데모는 브라우저에서 파일을 만들지 않고 어떤 항목이 들어가는지 목록으로만 보여줍니다.

    상태 초기화

    입금 기록, 필터, 대장 표시 설정, 선택한 투어를 처음 합성 데이터로 되돌립니다.

    이 데모와 실제 구현의 차이

    원본에서 확인한 것

    • 예약 폼, 관리자 화면, 대장 포털이 한 앱에 있고 대장은 투어별 서명 링크로 접근합니다.
    • 주민번호·여권 등 고유식별정보는 저장 시 암호화되고, 대장 응답에는 원문이 들어가지 않습니다.
    • 같은 회원이 여러 명을 묶어 예약하는 그룹 예약과 입금 대조 기능이 분리되어 있습니다.
    • 항공·숙소·보험 자료를 각각 내보내는 엔드포인트와 일정 내보내기 스크립트가 있습니다.

    이 데모에서만 하는 것

    • 금액·인원·입금은 실제 계산식이 아니라 이 데모에 정의한 단순 합계 규칙입니다.
    • 암호화·서명 토큰·권한 검사는 재현하지 않았고, 개인정보 가리기는 표시 형식만 흉내 냅니다.
    • 외부 API 호출, 파일 생성, 문자·알림톡 발송, 실제 저장은 하지 않습니다.
    • 모든 상태는 브라우저 메모리에만 있고 새로 고치면 초기값으로 돌아갑니다.

    출처 표기

    이 데모는 여행 예약·입금·명단 운영 웹앱 구조를 참고해 새로 작성한 별도 코드입니다. 원본 저장소와 실제 운영 서비스의 코드·데이터·회사명은 복사하거나 공개하지 않았으며, 서비스명과 도메인은 비식별 처리했습니다. 이름, 연락처, 여권·주민번호 형태의 값은 모두 합성 예시입니다.
